=========================================================
I2C의 SDL, SDA에 대한 보고서
-----------------------
## SCL(Serial Clock Line)
SCL은 통신의 동기 신호(클럭)을 전달하는 선이다. 마스터 장치가 클럭 펄스를 생성해서 데이터 전송 타이밍을 제어한다. 모든 데이터 비트는 이 클럭에 동기화되어 SDA선 상에서 샘플링된다.
## SDA(Serial Data Line)
SDA는 실제 데이터가 전송되는 양방향 신호선이다. 마스터와 슬레이브가 상황에 따라 송신자 또는 수신자가 되며, 하나의 선을 공유하여 반이중 방식으로 데이터를 주고받는다.
## 전기적 특성
SCL과 SDA는 모두 오픈 드레인 방식으로 구성되어 있다. 오픈 드레인 방식에서는 장치가 신호선을 LOW로 만들 수는 있지만 HIGH로는 만들지 못한다. 그래서 버스가 유후상태를 유지하게하기 위해 풀업 저항을 통해 VCC에 연결해야한다. <br>
이러한 구조 때문에 여러 장치가 같은 선을 공유해도 신호 충돌 없이 동작할 수 있다.
## I2C 통신 원리
> ### START, STOP 조건
SCL이 HIGH인 상태에서 SDA가 HIGH에서 LOW로 전환되면 START 조건이며, 반대로 SCL이 HIGH인 상태에서 SDA가 LOW에서 HIGH로 전환되면 STOP 조건이다.이 두 조건 이외의 구간에서는 SCL이 HIGH일 때 SDA가 변하지 않아야 데이터로 올바르게 인식된다.
> ### 데이터 전송 형식
데이터는 8비트 단위로 전송되며, MSB(최상위 비트)부터 순서대로 전송된다. 각 바이트 전송후에는 반드시 1비트의 ACK/NACK 확인 비트가 뒤따른다. 
> ### ACK/ NACK
수식 측에서 한 바이트를 정상적으로 수신하면 9번째 클럭 구간에서 SDA를 LOW로 유지하여 ACK를 보낸다. 반대로 더이상 데이터를 받을 수 없거나 수신 실패 시 SDA를 HIGH로 유지하여 NACK을 나타낸다.
> ### 슬레이브 주소 지정
START 조건 직후 전송되는 첫 번째 바이트는 7비트 슬레이브 주소와 1비트의 R/W 비트로구성된다. 버스 상의 보든 슬레이브는 이 주소를 자신의 주소와 비교하여 일치하는 경우에만 ACK로 응답하고 통신에 참여한다.
> ### 클럭 스트레칭
슬레이브 장치가 데이터를 처리할 시간이 더 필요한 경우, SCL선을 LOW상태로 붙잡아 마스터의 클럭 진행을 지연시킬 수 있다. 이를 클럭 스트레칭이라고하고 마스터는 SCL이 실제로 HIGH로 올라갈 때까지 기다려야한다.
## ATmega128의 TWI(I2C) 모듈
ATmega128은 하드웨어 TWI 모듈을 내장하고 있다. 이는 PORTD의 PD0(SCL), PDI(SDA) 핀을 통해 외부와 연결된다. 레지스터 설정을 통해 통신 속도, 주소, 인터럽트 여부 등을 제어할 수 있다. 
##  TWI 관련 레지스터
TWBR : SCL 클럭 주파수 결정을 위한 분주값 설정 <br>
TWSR : 현재 통신 상태 코드 확인, 프리스케일러 설정<br>
TWAR : 자신이 슬레이브로 동작할 때 사용하는 주소 설정<br>
TWDR : 송수신할 데이터를 저장<br>
TWCR : TWI 활성화, START/ STOP생성, ACK 여부, 인터럽트 플래그 제어<br>
***
SCL 클럭 주파수 계산 식<br>
SCL 주파수 = CPU clock / (16 + 2 * TWBR * 4^TWPS)
***
## TWCR의 주요 비트
TWINT : TWI 하드웨어 동작 완료시 1로 세트, 소프트웨어에서 1을 써서 클리어 <br>
TWEA : ACK 신호 생성 여부 제어
TWSTA : 1로 설정 시 START 조건 생성
TWSTO : 1로 설정 시 STOP 조건 생성
TWWC : TWDR 쓰기 충돌 발생시 세트되는 플래그
TWEN : TWI 모듈 활성화(1) / 비활성화(0), 활성화시 세트되는 플래그
TWIE : TWI 인터럽트 사용 여부 설정

UART 통신의 232통신과 485 통신에 대한 보고서
---------------------------
UART는 데이터를 시작비트, 데이터비트, 패리티비트, 정지비트로 구성하여 비동기 방식으로 직렬 전송하는 통신 규격이다.<br>
UART 자체는 논리 신호를 어떻게 구성할지에 대한 규격일 뿐이고, 신호를 실제 전선을 통해 얼마나 멀리, 얼마나 안정적으로 보낼 것인가는 별도의 전기적 규걱이 담당한다. <br>
이 전기적 규격에 RS-232와 RS-485가 있다

## RS-232 통신
### 정의
RS-232는 ELA에서 제정한 직렬 통신 표준으로 오랫동안 사용되어온 유선 시리얼 통신 규격이다.
### 전기적 특성 
+ 싱글엔디드 방식 : 신호선 1개 + 공통 접지(GND) 기준으로 전압을 비교
+ 1:1 통신 전용(하나의 송신기와 하나의 수신기만 연결 가능)
+ 최대 통신 거리 : 약 15m 내외
+ 최대 통신 속도 : 대략 20kbps수준
+ 주요 신호선 : TXD(송신), RXD(수신), GND(접지), 그 외 RTS/CTS/DTR/DSR 등 제어선 포함 가능

### 장점
+ 구조가 단순하고 회로 구성이 쉬움
+ 점대점 연결에서 구현이 간단하고 지연이 적음
+ PC, 레거시 장비와의 호환성이 높음

### 단점
+ 통신거리가 짧고 속도가 느림
+ 싱글엔디드 방식이라 외부 노이즈에 취약
+ 여러 장치를 한버스에 연결할 수 없음

## RS-485 통신
### 정의
RS-485는 EIA/TIA에서 제정한 차동 신호 방식의 직렬통신 표준으로 1대 다 연결을 할수 있어서 여러 장치를 하나의 버스에 연결해야 하는 환경에서 널리 사용된다.

## 전기적 특성
+ 차동 방식 : A선과 B선 두개의 신호선의 전압 차이로 놀리값을 판단한다
+ 멀티드롭 지원 : 하나의 버스에 최대 32개의 장치 연결 가능
+ 최대 통신 속도 : 최대 10Mbps수준
+ 노이즈에 강함 : 두 신호선에 동일하게 유입되는 노이즈는 차동 수신 시 서로 상쇄됨
+ 반이중 구성이 일반적이며, 필요시 4선을 사용해 전이중으로도 구성 가능

### 장점
+ 긴 거리 (최대 1.2km)까지 안정적인 통신 가능
+ 하나의 버스에 다수의 장치를 연결하는 멀티 드롭 네트워크 구성 가능
+ 차동 신호 방식으로 산업 현장의 전기적 노이즈에 강함
### 단점
+ 기본적으로 반이중 방힉이라 동시 송수신이 어려움
+ 멀티드롭 구성 시 종단 저항, 방향제어, 등 추가 설계 요소가 필요
+ RS-232에 비해 회로 및 프로토콜 설계가 다소 복잡함
